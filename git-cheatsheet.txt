-----------------------------------------------------
1. НАСТРОЙКА GIT (один раз на компьютере)
-----------------------------------------------------

git version
    Проверить, установлен ли Git и какая версия.
    Пример: git version 2.52.0.windows.1

git config --global user.name "ваш_ник"
    Указать имя пользователя для подписи коммитов.

git config --global user.email "ваша_почта@example.com"
    Указать email для подписи коммитов.

git config --global --list
    Показать все глобальные настройки Git.

-----------------------------------------------------
2. СОЗДАНИЕ И ИНИЦИАЛИЗАЦИЯ РЕПОЗИТОРИЯ
-----------------------------------------------------

mkdir имя_папки
    Создать папку.
    Пример: mkdir Lab2_ISRPO_Исенбекова

cd имя_папки
    Перейти в папку.
    Пример: cd Lab2_ISRPO_Исенбекова

pwd
    Показать текущий путь.

ls
    Показать содержимое папки.

git init -b main
    Инициализировать Git-репозиторий с основной веткой main.
    Создаёт скрытую папку .git — служебную информацию Git.

-----------------------------------------------------
3. СОСТОЯНИЕ РЕПОЗИТОРИЯ
-----------------------------------------------------

git status
    Показать, какие файлы изменены, добавлены, не отслеживаются.

    Расшифровка статусов:
    U (Untracked) — файл есть, но Git его не отслеживает.
    A (Added)     — файл добавлен в индекс (staging area).
    M (Modified)  — файл изменён после последнего коммита.

-----------------------------------------------------
4. ДОБАВЛЕНИЕ ФАЙЛОВ В ИНДЕКС (STAGING)
-----------------------------------------------------

git add имя_файла
    Добавить конкретный файл в индекс.
    Пример: git add README.md

git add .
    Добавить все файлы из текущей папки и подпапок.

git add -A
    Добавить все изменения (включая удаления).

git restore --staged имя_файла
    Убрать файл из индекса (отменить git add).

-----------------------------------------------------
5. СОЗДАНИЕ КОММИТОВ
-----------------------------------------------------

git commit -m "сообщение"
    Создать коммит с сообщением.
    Пример: git commit -m "Initial commit: create console app"

git commit -am "сообщение"
    Добавить все изменённые (не новые) файлы и сразу закоммитить.
    Не работает для новых (untracked) файлов!

-----------------------------------------------------
6. ИСТОРИЯ КОММИТОВ
-----------------------------------------------------

git log
    Полная история коммитов: хеш, автор, дата, сообщение.
    Выход из просмотра — клавиша q.

git log --oneline
    Компактный формат: один коммит = одна строка.

git log --oneline --all --graph
    История всех веток с ASCII-графом ветвления.

git log -3
    Последние 3 коммита.

git log --author="Имя"
    Коммиты конкретного автора.

git show хеш_коммита
    Показать подробности одного коммита и его diff.

    Обозначения в diff:
    --- a/...     — исходный файл
    +++ b/...     — изменённый файл
    +             — добавленная строка
    -             — удалённая строка
    @@@ -7,5 +7,6 @@@ — контекст изменений

-----------------------------------------------------
7. РАБОТА С ВЕТКАМИ
-----------------------------------------------------

git branch
    Показать все локальные ветки. Звёздочка * — текущая.

git branch -a
    Показать все ветки: локальные и удалённые (remotes/origin/...).
    Красный цвет — удалённые ветки (это не ошибка).

git checkout -b new-feature
    Создать ветку new-feature и сразу переключиться на неё (старый способ).

git switch -c new-feature
    То же самое, но современный синтаксис (Git 2.23+).

git checkout имя_ветки
git switch имя_ветки
    Переключиться на существующую ветку.

git switch -
    Переключиться на предыдущую ветку.

git branch -d имя_ветки
    Безопасно удалить ветку (если изменения слиты).

git branch -D имя_ветки
    Принудительно удалить ветку (даже если не слита).

git branch -m старое_имя новое_имя
    Переименовать ветку.

-----------------------------------------------------
8. ПОДКЛЮЧЕНИЕ УДАЛЁННОГО РЕПОЗИТОРИЯ
-----------------------------------------------------

git remote add origin URL_репозитория
    Подключить удалённый репозиторий под именем origin.
    Пример: git remote add origin https://github.com/user/repo.git

git remote -v
    Показать список удалённых репозиториев.

git remote remove origin
    Удалить привязку к удалённому репозиторию.

-----------------------------------------------------
9. ОТПРАВКА ИЗМЕНЕНИЙ (PUSH / PULL)
-----------------------------------------------------

git push -u origin main
    Отправить ветку main на сервер и запомнить связь (флаг -u).
    После первого раза достаточно git push.

git push -u origin new-feature
    Отправить новую ветку на сервер.

git push
    Отправить текущую ветку (если уже настроен upstream).

git pull
    Забрать изменения с сервера и слить с локальной веткой.

git fetch --prune
    Загрузить информацию о ветках и удалить ссылки на несуществующие.

10. ПРОБЛЕМЫ И ИХ РЕШЕНИЯ (из практики)
-----------------------------------------------------

Проблема 1: git commit пишет "nothing to commit"
    Причина: файл не создан или не добавлен в индекс.
    Решение: сначала создать файл (touch README.md),
             затем git add README.md, потом commit.

Проблема 2: git log --oneline. (с точкой) выдаёт
            "fatal: unrecognized argument: --oneline."
    Причина: точка в конце команды. Git воспринимает её
             как часть флага, а такого флага нет.
    Решение: убрать точку — git log --oneline

Проблема 3: git push выдаёт
            "The current branch has no upstream branch"
    Причина: ветка ещё не связана с удалённой.
    Решение: git push --set-upstream origin имя_ветки
             (или флаг -u: git push -u origin имя_ветки)

Проблема 4: при git push просит логин и пароль
    Причина: GitHub/GitFlic не принимают обычный пароль.
    Решение: использовать Personal Access Token или
             SSH-ключ. При первом push откроется
             Git Credential Manager — ввести токен.

Проблема 5: git remote add origin выдаёт
            "remote origin already exists"
    Причина: origin уже добавлен ранее.
    Решение: git remote remove origin, затем заново
             git remote add origin URL

Проблема 6: создал репозиторий на GitHub с README,
            теперь push отклоняется (rejected)
    Причина: истории локального и удалённого
             репозиториев не совпадают.
    Решение: либо удалить репозиторий на GitHub и
             создать заново пустым, либо выполнить
             git pull origin main --allow-unrelated-histories
             и потом git push.

Проблема 7: в git branch -a удалённые ветки красные
    Причина: это стандартная подсветка Git.
    Решение: ничего делать не нужно — это не ошибка.
             Красный = ветка на сервере, не локальная.

Проблема 8: при вводе нечисла программа падает с
            FormatException (для C#-задач)
    Причина: Convert.ToInt32 не умеет обрабатывать
             плохой ввод.
    Решение: использовать int.TryParse:
             int n;
             while (!int.TryParse(Console.ReadLine(), out n))
             {
                 Console.Write("Не число, попробуйте ещё: ");
             }

11. КОМАНДЫ ДЛЯ РАБОТЫ С GITFLIC/GITHUB
-----------------------------------------------------

# Создание репозитория — через веб-интерфейс:
#   1. Зайти на gitflic.ru (или github.com)
#   2. Создать новый публичный репозиторий
#   3. НЕ ставить галочки README, .gitignore, лицензия
#   4. Скопировать URL репозитория

# Подключение:
git remote add origin https://gitflic.ru/project/user/repo.git
git remote -v

# Отправка:
git push -u origin main

# Отправка второй ветки:
git switch feature
git push -u origin feature

# Просмотр всех веток (локальных и удалённых):
git branch -a

-----------------------------------------------------
12. МОИ ПРИМЕРЫ ИЗ ЛАБОРАТОРНОЙ РАБОТЫ
-----------------------------------------------------

# Инициализация репозитория:
git init -b main

# Первый коммит:
git add .
git commit -m "Initial commit: create console app"
git log --oneline
# → b12c280 (HEAD -> main) Initial commit: create console app

# Создание ветки:
git checkout -b new-feature
git branch
# → * new-feature
#     main

# Второй коммит в новой ветке:
echo 'Console.WriteLine("Hello from branch");' > task.cs
git add task.cs
git commit -m "Add task file"
git log --oneline
# → 4a5b6c7 (HEAD -> new-feature) Add task file
#    875453c (master) Add README

# Отправка:
git checkout master
git push -u origin master

# Возврат в feature и отправка:
git checkout new-feature
git push -u origin new-feature

# Проверка всех веток:
git branch -a
# → * new-feature
#     master
#     remotes/origin/master
#     remotes/origin/new-feature
